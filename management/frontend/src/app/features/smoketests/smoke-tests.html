Pipeline tests

One catalogue of questions, put to a use case's own pipeline, and judged by a person. Every use case is asked all of them, which is what makes two of them comparable. Testing a model is a use case whose pipeline starts there. Nothing here decides whether an answer is good — the rating carries the name of whoever gave it.

Run the catalogue against a use case Every question in the catalogue, in order, one at a time, through that use case's own pipeline — so a filter, a router or a redactor is exercised exactly as it would be in production, and a blocked question is a result rather than a broken run. Sequential because firing a hundred at once would trip the use case's own rate limit and produce a run full of 429s that says nothing about anything.
